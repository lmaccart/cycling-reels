# Cycling Reels

This folder is a pipeline: raw footage → library of tagged moments → reel plans (JSON) → rendered Reels (Remotion) → a posting queue. You do the judgment (classifying, choosing moments, picking music, writing text); the `./reels` CLI does the media work. Run every command from the project root.

## Rules that always apply

- **Visuals are the user's own footage unless they say otherwise.** Reels are built from clips and photos in `library/` (what they recorded and dropped in `inbox/`). Generated visuals — motion graphics, animations, synthesized video, images, B-roll, backgrounds or title cards — need the user's explicit permission first: ask in the conversation, say what would be generated and where it would be used, and wait for a yes. Permission covers what was asked, not later reels or other kinds of visual. Never download or screen-grab visuals, never ask for "stock" shots, and the AI features of outside editors such as Kino stay off ([reference/kino.md](reference/kino.md)). The renderer verifies each file against the original it ingested and refuses anything else. Short on material? Make fewer reels and say so. The one exception is **exhibits**: study screenshots and diagrams the user put in `exhibits/`, and charts of their own numbers, shown as overlays the rider points at ([reference/exhibits.md](reference/exhibits.md)) — never fetched or generated, never a shot of their own.
- **Music: this week's trending Reels songs.** Each batch, check the current trending-audio lists and pick songs that fit the reels ([reference/music.md](reference/music.md)). Download the official audio from YouTube with `./reels music add <url> --instagram "<title> <artist>"`; it's mixed into the reel, and Instagram usually recognizes it and shows the song. If the user gives a link, use that song. No-copyright tracks (`./reels music search … --free`) are for talking reels or when the user wants no mute risk. Music is never generated; never pick a track flagged `⚠` without the user's say-so. Attaching Instagram's licensed copy at scheduling instead is opt-in (config `audio.attachSongs`).
- **Sound effects: the free library or the user's own ride audio.** Only sounds in `sfx/` (human-made, CC0 or Pixabay licence, source and author recorded per file) or cut from the user's footage with `./reels sfx add --from`. Never AI-generated sounds unless the user explicitly asks for them.
- **Write like this person, not a brand.** [reference/character.md](reference/character.md) says who is talking: what they're working toward, how they sound in their own words, the recurring people and bits, and what they don't sound like. Hooks, on-screen text and captions then follow [reference/captions.md](reference/captions.md): lowercase, casual, specific, a little funny; no hype words, no ALL CAPS (except when copying a trend that uses them — [recipes.md](reference/recipes.md#formats)), at most one emoji; captions short and dry. Text renders exactly as you write it. When the user rewrites text, record both versions as a voice sample (`./reels review feedback --category preference --kind text-edit`).
- **Never publish or schedule a reel the user hasn't approved.** Approval means they saw it (or its preview) and said yes, in this conversation. "Approve this batch" counts for that batch only.
- **Don't invent facts.** Speeds, grades, distances, watts, race results and place names must come from the user, the footage itself (a bike computer in frame, a road sign) or a transcript. Otherwise write text without numbers. Camera GPS from GoPro telemetry counts as the footage (the user confirmed): show it only through `"value": "gps…"` stats so the number comes from the data — never type a speed in by hand. GoPro altitude drifts badly, so no elevation numbers. Strava data from the user's own account counts as the user giving the number (incl. heart rate and power): show it only through `"value": "strava:…"` stats. Never put other athletes' Strava names or data on screen.
- **Be careful with other people.** Avoid close-ups of identifiable strangers and don't feature anyone's crash unless the user says it's fine. Tag `people` honestly so this is visible at planning time. Collab invites and people tags (`post.collaborators`, `post.peopleTags`) only for handles the user gives you, of people who are in the reel or agreed.
- Keep the user's originals: never edit anything in `library/media/`, and never delete from it except whole chapters through `./reels prune --apply`, one round at a time, after the user approves that exact list in this conversation.

## Weekly batch (the normal flow)

0. **Learn before planning** — follow [reference/learning.md](reference/learning.md): refresh/import analytics when available, run `./reels review`, and read `learning/LESSONS.md`, this/last week's review JSON and `learning/experiments.json`. Record evidence-backed strengths, weaknesses and next actions across audience response, user preferences and production quality. Missing/stale data is unknown, not failure. Pull the account numbers too (followers, account reach, accounts engaged — [reference/analytics.md](reference/analytics.md#account-numbers)): growth is judged on followers, not only on single reels. Aim for five familiar approaches and two tests in a seven-reel week if footage permits. **Keep at most two questions open and repeat each for three weeks or more** (same `question`, new id each week) rather than starting new one-reel tests; register each run's hypothesis, one change, primary metric and test/control slugs before rendering. No automatic winners or permanent skill/code rewrites.
1. **Ingest** — `./reels ingest` moves new files from `inbox/` into the library, makes a contact sheet per asset, detects talking, finds candidate ride sounds and reads GoPro GPS (`library/telemetry/<id>.json`; `./reels show <id>` prints good-fix time, max/avg speed and distance). Then fetch the new footage's rides from the Strava connector and `./reels strava import` them ([reference/strava.md](reference/strava.md)); ingest links clips to rides already imported and names days still missing one.
2. **Classify** — `./reels pending` lists what needs tags. For each asset:
   - Read its contact sheet image(s) (`library/sheets/<id>.jpg`; long clips have `-2`, `-3` sheets). Tiles are labelled `#n  m:ss.s`; on landscape footage the yellow lines show the default 9:16 crop.
   - `./reels show <id>` gives audio/speech info. For a closer look: `./reels frames <id> --start 40 --end 70` (zoomed sheet) or `--at 52.5,55` (big frames for crop decisions).
   - **Sounds:** `./reels sounds <id>` lists candidate ride sounds (freehub, shift/clip-in, pass-by, brakes, car…) and writes `library/sounds/<id>.jpg`: loudness + spectrogram with click / wind / speech lanes and the candidates boxed (zoom long clips with `--start A --end B`). Read it, cross-check the frames, and tag only clean, audible ones in `sounds` per [reference/taxonomy.md](reference/taxonomy.md#sounds-video), never something buried in wind or talked over. Detection is a shortlist, not a verdict: freehub is fairly reliable, shifts and pass-bys much less so.
   - Save tags: `./reels tag <id> --json '{…}'` following [reference/taxonomy.md](reference/taxonomy.md). Moments are the 2–8 s stretches worth using, with `focusX` = where the subject sits horizontally (0 left … 1 right) so the 9:16 crop keeps it.
   - **Shelves on every moment:** `role`, `speaker`, `face`, `mood`, `opener`, plus `line` (voice only), `thread` and `beat` when they apply, using the written definitions and borderline cases in [taxonomy.md](reference/taxonomy.md#shelves). Judge them from the transcript and frames, not the label: `speaker: me` needs real evidence, and `opener` stays selective. Labels must say what's in the shot, so the moment can be found by reading. `./reels tag` warns when a moment is missing a shelf; fix it with `./reels tag <id> --merge --json '{"moments":[{"id":"m-…","role":"…"}]}'`.
   - The user films from [SHOTLIST.md](../../../SHOTLIST.md) (pass-bys, face at the hard moment, one line to camera, the computer screen, kit-up, café…). Tag those honestly so plans can find them: `roadside` for pass-bys, `chase` for third-person views, `selfie` for face clips, `screen` for a bike computer, `talking` type for lines to camera.
   - Junk (lens cap, pocket footage, blurry): `./reels skip <id> --reason "…"`.
   - **360 footage** (GoPro MAX/MAX 2 `.360`, 360 MP4s and photos — the sheet says `360°` and shows the whole sphere unwrapped with yaw labels): find the road and the rider, check with `./reels frames <id> --views` / `--view yaw,pitch,fov`, and save them as named `angles` ([reference/taxonomy.md](reference/taxonomy.md#360-footage-gopro-max--max-2-360-360-mp4s-360-photos)). Plans then aim a virtual camera with `view`, camera moves with `path`, or `projection: "tiny-planet"` ([reference/plan-schema.md](reference/plan-schema.md#360-segments-gopro-360-360-mp4s-360-photos)).
3. **Transcribe talking clips** — `./reels transcribe` (only clips with detected speech). Check each with `./reels show <id>`. Fix misheard cycling words by editing the `w` values in `library/transcripts/<id>.json` (keep the timings). If it's wind noise turned into gibberish, don't use `captions: "transcript"` for that clip.
4. **Plan** — **start from the rider's line or a story, then cut footage under it**, rather than picking the best moments and writing text over them ([reference/recipes.md](reference/recipes.md#start-from-the-voice)). Short reels feel chopped when nobody talks and nothing happens. **Weekly mix: at least 4 of 7 reels voice-led, at most 1 pure montage.** Find the spoken lines first (`./reels library --role voice --speaker me --unused`, `./reels search "<words>"` for a remembered line or place, which also finds spoken lines nobody tagged) and the stories with a setup, a turn and a payoff (`./reels stories`, which also shows the beats a series still needs). `./reels shelves` shows what's in stock and what's low. **Series first:** give each running series in [recipes.md](reference/recipes.md#series) its episode on its day when the footage has one, and skip an episode rather than fake it. Then fill in the footage under each line with `./reels library --unused --min-score 3` (available moments, best first) and shelf filters. Pick the week's reels (default 7, one per day) using [reference/recipes.md](reference/recipes.md): a person on screen, a payoff the footage shows, a mix of formats (trend, story, tips, POV joke, beat edit…), and never the same clip in two reels. Before choosing, read how the last reels did: pull analytics per [reference/analytics.md](reference/analytics.md) (Metricool, brandId 7655493), `./reels stats import <file>`, then `./reels stats`, and read `out/PERFORMANCE.md` — hold rate, watch-through, views/reach (replays), shares/saves/comments and engagement per reach steer formats, hooks, lengths and songs; act on big gaps only. For each reel:
   - **Spine:** set `"spine"` to what carries the reel: `voice` (a spoken line from the rider), `story` (a setup, turn and payoff a stranger could retell in a sentence), `sound` (a real sound event, like the train horn) or `trend` (a trend format). `./reels check` warns when it's missing, when `voice` has under 30% voice, and when a 7-reel batch misses the weekly mix ([reference/plan-schema.md](reference/plan-schema.md#spine)). Voice-led reels may run 15–40 s; the 7–13 s lesson (aud-length-01) doesn't cap them, since it came mostly from comparing against montages.
   - **Format:** set `"format"` to the recipe name from recipes.md so performance can be compared by format.
   - **Music:** fetch this week's trending lists and shortlist songs per [reference/music.md](reference/music.md) (fits the footage, official audio), add each with `./reels music add <url> --instagram "<title> <artist>"`, and plan `"music": {"track": "<slug>", "cutOnBeat": true}` (it starts at the loudest part; set `start` for a trend's exact moment). Reuse a song only while it's still on the lists. No-copyright tracks (`--free`) carry their credit line automatically.
   - **GPS: Strava first.** For a clip linked to a Strava ride, use `strava:speed` and `"route": "strava"`. GoPro GPS (`"gps"`, `gps:max`, `gps:avg`, `"route": true`; `./reels telemetry <id> --fast 5` finds the fastest stretches) is only for clips with no ride, or gaps in the Strava streams. `./reels check` enforces this ([reference/plan-schema.md](reference/plan-schema.md#gps-strava-first-gopro-only-when-needed)).
   - **Road to 5 W/kg:** `"progress": {"asOf": "<recording date>"}` adds the series bar from `./reels progress` entries. Log only the FTP and weight the user says (`./reels progress set --ftp … --weight … --date …`) ([reference/plan-schema.md](reference/plan-schema.md#progress-bar-road-to-5-wkg)).
   - **Strava (any clip filmed on a recorded ride):** `./reels strava list` shows each ride's numbers and linked clips; `"stats": [{"value": "strava:speed"}]` (also `strava:power`, `strava:hr`, `strava:distance`, `strava:moving-time`, …) and `"route": "strava"` ([reference/plan-schema.md](reference/plan-schema.md#strava-stats-and-route-map-the-linked-ride)). Fetch and import rides per [reference/strava.md](reference/strava.md).
   - **Swearing:** add `"bleep": true` on any segment where the clip's own audio swears; `./reels check` warns about unbleeped swear words ([reference/plan-schema.md](reference/plan-schema.md#bleeps)).
   - **Punch-ins / loops (optional):** `"punch": [{"at": 1.2, "scale": 1.15}]` or `{"words": ["no", "way"]}` on a captioned clip zooms the footage for emphasis; `"punchOnBeats": {"every": 4}` with a beat-synced song. `"loop": true` for 6–12 s reels that should replay seamlessly — end on the lead-in to the first shot (swap halves, see recipes.md Loops) and read the `seam:` line in `./reels check` ([reference/plan-schema.md](reference/plan-schema.md#punch-ins)).
   - **Long talking takes:** `./reels takes <id>` lists the recording as phrases split at the pauses, each with a tight in/out, repeated takes of a line grouped (`★ last take`), and notes on false starts, trailing words, filler and repeats. Pick the phrases for the script and get the segments with `--pick 2,5-7` (in the reel's order). It proposes; read the lines and still check the result with `./reels check` and `./reels look` ([reference/plan-schema.md](reference/plan-schema.md#cutting-a-long-take)).
   - **Talking clips:** keep the voice going over the ride with `cutaways` (B-roll laid over the talking segment; its audio and captions carry on) every few seconds, back on the face for the punchline ([reference/plan-schema.md](reference/plan-schema.md#cutaways)).
   - **Pointing at a study or chart:** `"exhibits": [{"image": "<file in exhibits/>", "at": 1.2, "for": 4, "x": 0.66, "y": 0.34}]` on the talking segment puts the user's screenshot, diagram or a chart on screen; `"anchor": "hand"` places it from the pointing fingertip and `"depth": "behind"` puts the rider in front of it. Check placement with `./reels exhibits preview <plan>` ([reference/exhibits.md](reference/exhibits.md)).
   - **Text:** hook, 1–3 text beats, a short dry `post.caption` (a short dry question is fine, not required — [reference/captions.md](reference/captions.md#instagram-caption-postcaption)), 3–5 hashtags and alt text in the natural voice of [reference/captions.md](reference/captions.md). Collabs/tags (`post.collaborators`, `post.peopleTags`) only with handles the user gave.
   - **Sound:** 1–2 ride-sound moments (`"nat"`) on the best sounds in the shots you picked (`./reels library --sounds`, `./reels sounds <id>`), at most one `musicDrops` ending where the `"payoff": true` segment starts, and **no sound effects unless the user asks for them on that reel** (automatic cues are off by default; when asked, `"autoSfx": true` and/or `sfx` cues, a few at most). Read the sound sheet `./reels check` prints and act on its quiet-nat and trending-song warnings (freehub moments usually need `volume` 2–4) — [reference/recipes.md](reference/recipes.md#sound-design), [reference/plan-schema.md](reference/plan-schema.md#sound-design). For a no-music "just the bike" reel, leave `music` out and set `"autoSfx": false`.
   - Write `plans/<YYYY-MM-DD>-<slug>.json` per [reference/plan-schema.md](reference/plan-schema.md) and validate with `./reels check plans/<file>.json` (or the whole batch at once); fix every error and any warning that matters — including the `retention:` ones (photo opening, an opening with no face and nobody talking, slideshow fades, 5 s+ with nothing changing), captions cutting into words, and footage another reel already used.
5. **Render** — `./reels render plans/<file>.json`, one plan per command. Then Read `out/<slug>/preview.jpg` and check: hook readable and not covering the subject, subject inside the crop, nothing colliding, text sounds like a person, the payoff visible. For loop reels, render prints `loop seam:`; fix a visible jump before review. Then **`./reels look <slug>`** (several slugs at once is fine): Read every `out/<slug>/look/strip-NN.jpg` — a frame each 0.5 s plus one right after every cut, text beat, punch-in and exhibit — and check each shot's crop, text over faces, captions stuck or cut off, shots that hold too long, exhibits covering the rider. Read its report too: cut-to-beat offsets, the mix's loudness per second, and the voice / ride sound against the music under them (measured on the sources). Act on its `flags` (voice under 6 dB over the music: raise that segment's `volume` or lower the music; a quiet hole that isn't a drop; a muted captioned clip) or tell the user why one is fine. You still can't hear it or see motion: say so rather than calling a mix "good". Fix the plan and re-render when something's off. **Colour** is automatic: every clip gets the colour-space fix (P3 etc. to BT.709) while staging, but no colour look by default (`render.grade.look` is `none`); a plan or segment `"grade": {…}` without a `look` turns the `house` look on for that scope (unless a `"none"` or a `look` is already set above it, which is kept) (one `grade` line per clip in the render log). In the strips, check skin, kit colours and skies look natural; adjust a clip with `"grade"` (`warmth`, `exposure`, `strength`, `look`) rather than changing the look — the user wants it mild and the same across reels, not saturated and not shot-matched ([reference/plan-schema.md](reference/plan-schema.md#colour-grade)).
6. **Review with the user** — show each reel's preview, hook, caption and music (song — artist, trending or free track), and point them to `out/<slug>/reel.mp4` to watch (with attaching on, `preview.mp4` — `reel.mp4` is then the upload without the song). Say which three reels should be pinned on the profile now and why ([reference/publishing.md](reference/publishing.md#pinned-reels)); the user pins them in the app. Apply their edits (if they'd rather review on a timeline or send notes at exact moments, `./reels project` hands the reel to Kino or Remotion Studio — [reference/kino.md](reference/kino.md); changes still come back as plan edits and a local re-render). `./reels mark <slug> approved` for each yes (`./reels mark rendered approved` when they approve everything they just reviewed); `./reels discard <slug>` for each no (frees its clips).
7. **Queue and schedule** — `./reels queue` gives approved reels daily slots (unapproved ones are left alone) per config `schedule.times` / `schedule.timezone` and writes `out/QUEUE.md`. Then follow [reference/publishing.md](reference/publishing.md): schedule each queued reel through the Metricool connector if it's available, and record it with `./reels mark <slug> scheduled --metricool-id <id>`. Without a connector, hand the user `out/QUEUE.md` or `./reels export` for manual posting.
8. **Close the production review** — record actual user edits/rejection reasons and visual/audio/scheduling issues with `./reels review feedback` as they happen (before discarding rejected reels). After scheduling, run `./reels review close --slugs <all intended batch slugs> --file <notes.json>` per [reference/learning.md](reference/learning.md). Include unresolved/manual posts; don't mark scheduled unless confirmed. Record which lessons influenced each reel, experiments and proposed improvements. Scheduling isn't publication: evaluate audience outcomes next week. Permanent skill/recipe/shot-list/code changes need approval; code changes need tests.
9. **Send the filming card** — write `FILM-THIS-WEEK.md` (replacing last week's) and give it to the user in the conversation: what to film before the next batch so next week's reels exist. Build it from what is actually short, not from the whole shot list: the next episode of each series and the beats it still needs (`./reels stories`), the low shelves (`./reels shelves`: openers, reactions, proof), one item from character.md's "Outside the bike", and the formats this batch couldn't make. Keep it to one screen: at most six items, the must-haves marked ★, and two or three specific questions to answer to camera (from this week's real plan, never a script to read). Nothing on it may ask for a staged fact. [SHOTLIST.md](../../../SHOTLIST.md) stays the full reference for how to film each shot.

## When running unattended (a scheduled task)

Nobody is there to approve, so do steps 0–5 only, then stop: don't approve, queue, upload or schedule anything, and don't close a scheduling checkpoint. An unattended run must never apply a prune round (`./reels prune --apply`): `--dry-run` at most, and put the list in the report. Run the planning learning review even with no new footage; include its path, experiments and proposed permanent changes in the report. The analytics pull needs the Metricool connector; if it isn't available, plan from the last `out/PERFORMANCE.md` and saved learning records and say so. Music: check this week's trending lists and add songs with `--instagram` as usual (nothing is published), or use tracks already in `music/` / `--free` results without a `⚠` caution. If the inbox is empty and fewer than 3 good unused moments remain, render nothing and say the library is running low. Write the filming card (step 9) into the report too. Finish with a short report: what was ingested, which reels were rendered (slug, hook, length, music, preview path), anything skipped or uncertain, and how much unused material is left (`./reels library --unused`).

## Command reference

| Command | What it does |
| --- | --- |
| `./reels doctor [--fix]` | Checks ffmpeg, Node, Remotion, Whisper, yt-dlp; `--fix` installs/updates what's missing |
| `./reels ingest` | Inbox → library, contact sheets, speech detection; queues and then prepares front/back source proxies for new 360 videos |
| `./reels prewarm-360 [--all] [ids…]` | Backfill front/back and whole-clip aim proxies (aim in ≤180 s chunks, including medium stabilization corrections); no arguments resumes the pending ingest queue. Prints bytes written and stops before its next output reservation would leave under 50 GB free |
| `./reels pending` | Assets waiting for tags |
| `./reels frames <id> --start A --end B` / `--at t1,t2` | Closer looks at a clip (also works on `out/<slug>/reel.mp4`) |
| `./reels frames <id> --views` / `--view rider` or `--view 180,-15,85` / `--planet` (360 only) | Four directions, or a preview of an exact 9:16 reframe / tiny planet |
| `./reels tag <id> --json '{…}'` / `./reels skip <id>` | Save classification (moments keep their ids when their spans match) |
| `./reels tag <id> --merge --json '{…}'` / `./reels tag-batch --file f.json` | Partial update: only what's given changes, moments addressed by id; batch saves nothing unless all are valid |
| `./reels tag-backfill` | Give an id to any moment that lacks one |
| `./reels show <id>` | Everything about one asset, incl. moments and usage |
| `./reels flag <id> [--in A --out B] [--note "…"]` / `./reels flags [--json]` / `./reels unflag <flag-id>` | Flagged clips (`flags.json`): ranges the user or Claude marked to come back to — the editor shows them under Flagged in the Library. Read them when planning; they change no tags |
| `./reels transcribe [ids…]` | Word-level transcripts (default: clips with speech) |
| `./reels library [--unused] [--min-score N] [--type T] [--role R] [--mood M] [--speaker S] [--face\|--no-face] [--opener] [--line L] [--thread T] [--recent] [--include-deleted]` | Tagged moments, best first (`--recent`: newest footage first). Deleted footage is hidden unless asked for, and never counted as available |
| `./reels search "<words>" [--phrase] [same filters] [--limit N] [--json]` | Finds footage in moment labels, summaries, hooks, notes, landmarks and transcripts. All words must match within one field; `"double quotes"` inside the query or `--phrase` for exact wording. Transcript hits give the spoken line with exact in/out, the moment it falls in or `untagged`, and `[low-conf]` for likely Whisper inventions |
| `./reels takes <id> [--start A --end B] [--pause 0.5] [--no-audio] [--pick 2,5-7] [--json]` | Cut list for a long talking take: phrases split at pauses with in/out snapped to the words (and to the audio level when the clip is quiet enough), retakes grouped with the last one marked, false starts / trailing words / filler flagged; `--pick` prints the chosen phrases as plan segments |
| `./reels shelves [--include-deleted]` | Stock per role (total / unused / unused 3+), unused openers and voice by me, low shelves, strong unused moments |
| `./reels stories [<thread>] [--include-deleted]` | Story threads and which beats they have; with a thread, its moments by beat and what's missing |
| `./reels sounds <id> [--start A --end B] [--best] [--kind K]` / `--pending` | Candidate ride sounds + labelled spectrogram `library/sounds/<id>.jpg`; `--pending` analyses every video without a cache |
| `./reels library --sounds [--kind K] [--unused]` | Tagged ride sounds, best first |
| `./reels telemetry [ids…] [--force]` | Read GPS from GoPro telemetry (ingest does this automatically; not tracked in git) |
| `./reels progress` / `progress set --ftp W --weight kg --date D` | Road to 5 W/kg entries (user-given FTP and weight) for the progress bar |
| `./reels telemetry <id> --at 120.5` / `--start A --end B` / `--fast 5` | Speed at a moment, min/avg/max over a range, fastest gap-free stretches |
| `./reels strava import <file.json> [--activity ID]` / `./reels strava list` / `./reels strava link` | Store a Strava connector response (ride list, performance, streams) and link clips; list rides + linked clips; re-link |
| `./reels sfx list [--category C]` | Sound effects in `sfx/` (whoosh, swish, riser, hit, pop, click, shutter, bell, scratch, stop, nat) with length, level, license, author |
| `./reels sfx add <file-or-url> --name <slug> --category C --license CC0-1.0 --source <page-url> --author "<name>" [--trim A,B]` | Add a CC0 / Pixabay-licence sound (trimmed, 48 kHz WAV, normalized); refuses without license + source |
| `./reels sfx add --from <asset-id> --at <s> --for <s> --name <slug> [--clean]` | Cut a sound out of the user's own footage (category `nat`); `--clean` = highpass + denoise for wind |
| `./reels stats import <file.json>` / `./reels stats [--since YYYY-MM-DD]` | Store a Metricool analytics pull and match it to reels (a pull whose fields are all `IGEV…` is stored as account numbers by day in `analytics/account/`) / per-reel performance table, Footage section (opening shot, mix, score calibration) and Account section (followers, account reach, accounts engaged beside the reel posted that day), writes `out/PERFORMANCE.md` |

360 proxies live under `.cache/editor/live/preview/`, shared with the editor; originals are only read. Ingest queues each new 360 video immediately after saving its asset, before sound processing or the next clip, then drains that durable queue serially after the other ingest work. Interrupted, failed or disk-blocked entries can be resumed with `./reels prewarm-360`. Explicit IDs and `--all` also prepare every aim range. Repeated runs reuse matching cached media, including a larger aim range covering a split piece. Correction quaternions use the requested interval's own source-time clock, not the cached media start; `lock` stays anchored to the request start whether the media is warm or cold.

Both proxies prefer native Metal reprojection plus hardware H.264 (then HEVC) on supported 8-bit SDR BT.709 spherical video. Front/back keeps the worker's measured travel/gravity/tagged views at 1440×1280; aim is an unstabilized 2048×1024 sphere, 30 fps, up to 180 s. The proxy preset is 8 Mb/s target, 12 Mb/s ceiling, 10-frame GOP, no B-frames, 8-bit 4:2:0 with the source's full/limited range—not the renderer's ~31 Mb/s preset. HDR, other layouts/colour, unsupported timing and missing helpers use the accurate ffmpeg/v360 path with an explicit reason, preferring VideoToolbox then libx264. Prewarm and worker results report the actual backend/encoder. `REELS_SPHERE_BACKEND=metal` requires native execution; `v360` forces the reference path. Proxy workers receive only the named AGX/IOSurface, Metal compiler and codec services, plus read/execute access to the trusted helper/metallib; no broader filesystem/network access. `scripts/reels/editor/proxy.py:PROXY_VERSION` is **5** for this pixel/codec contract. Version-4 entries stay on disk but are not mixed with version 5; compatible version-5 covering ranges remain reusable across backend availability, ordinary source edits and frozen renderer revisions. Trusted encoding/reservation/correction helpers do not come from frozen snapshots.

Measured cold in the actual worker sandbox on `260627-gs010096-7da3`, 0–30 s/900 frames: front/back software **14.814253 s**, W5b **10.643911 s**, Metal **5.652135 s** (30,628,341 bytes); aim software **14.001434 s**, W5b **10.591574 s**, Metal **5.993431 s** (30,637,650 bytes). Aim is **2.336130×** the original baseline, **1.767197×** W5b—not a warm hit. All video PTS and audio PCM/packet clocks matched. **Encoded PSNR ≥35 dB is still unmet** on some samples (minimum 32.594121 dB against W5b); raw projection parity is ≥68.306652 dB and does not waive that gate. `./reels bench-proxy-metal --asset 260627-gs010096-7da3 --seconds 30` retains a failing exit for the unmet parity gate. Full timings, bytes and PSNRs: `editor/README.md`, Metal proxy preparation. Do not run whole-library prewarm as a verification step.

CLI prewarm does **not** join the editor's in-process job queue. Both paths instead hold the same cross-process lock per proxy key through lookup, encoding and atomic media/marker publication; duplicate requests wait and then reuse the completed entry. Startup cleanup takes that lock nonblockingly and skips active work, even if a partial is old. Finished entries are never pruned by prewarm or startup cleanup. Shared on-disk reservations account for concurrent proxy jobs before any new output is written. Encoders inherit the key lock and reservation descriptors: SIGINT or SIGKILL of Python cannot release them while an encoder still writes. Abandoned reservations are recovered only after both Python and the encoder exit. The conservative guard can stop with more than 50 GB free; unrelated disk writers are outside the reservation. Existing editor cache hits remain playable without a new disk reservation; when a requested CORI sidecar is missing and disk reservation fails, corrections are computed in memory without persisting them.

Prune rounds bind each listed asset to its media path and file identity (resolved path, device, inode, size and modification/change timestamps). A changed or replaced file is skipped. Older rounds require a fresh dry run and approval. Plan protections use the renderer's exact ID resolver, including prefixes and substrings; unreadable or unresolved plans stop pruning.

Track records live in `music/<slug>.json`; you may fix a wrong `credit` there, or set `"rightsOk": true` when the user confirms they have the rights.

`ingest` (on long GoPro files — 360 `.360` files especially), `transcribe`, `music add` and `render` can each take several minutes: give those commands the maximum Bash timeout (10 minutes) or run them in the background, one plan per `render` call.

If a command fails with "run ./setup.sh first" or a missing dependency, run `./reels doctor` and tell the user exactly what to install rather than working around it. If YouTube downloads start failing, `./reels doctor --fix` updates yt-dlp.
